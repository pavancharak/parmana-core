# Tutorial 25 — Execution Permit Generation

## Overview

This tutorial introduces the **Execution Permit**, one of Parmana's core security primitives.

An Execution Permit is generated only after a Business Transaction has been evaluated against the requested policy and the policy decision authorizes execution.

The permit cryptographically binds the approved action to its authorization so downstream systems can verify exactly what was approved.

---

## Execution Flow

```
Business Transaction
        │
        ▼
Policy Evaluation
        │
        ▼
Decision
        │
        ▼
Execution Permit
        │
        ▼
Execution
```

Execution is only authorized after a successful policy evaluation.

---

## What is an Execution Permit?

An Execution Permit is a cryptographically signed authorization generated by the Parmana Runtime.

It contains information including:

- Authorization ID
- Decision ID
- Business Transaction ID
- Policy Name
- Policy Version
- Issue Time
- Expiration Time
- Executable Content Hash

The permit is digitally signed to prevent unauthorized modification.

---

## Building the Runtime

The Runtime generates the Execution Permit automatically.

```ts
const runtime = new RuntimeBuilder()
  .withPolicyRepository(new FilePolicyRepository("policies"))
  .build(repository);
```

No additional configuration is required.

---

## Executing a Business Transaction

```ts
const { context } = await runtime.execute(transaction);
```

The generated Execution Permit is available from the Runtime Context.

```ts
const permit = context.authorization.authorization;
```

---

## Permit Metadata

The permit contains authorization metadata.

Typical fields include:

```text
Authorization ID
Decision ID
Policy Name
Policy Version
Issued At
Expires At
```

These fields uniquely identify the authorization granted by Parmana.

---

## Digital Signature

The permit is digitally signed.

The Runtime also returns signature metadata.

Typical fields include:

```text
Algorithm
Key ID
Signature
```

Applications can later verify that the permit has not been modified.

## Why Execution Permits?

An Execution Permit provides cryptographic proof that:

- A policy was evaluated.
- The requested action was authorized.
- The authorization belongs to a specific Business Transaction.
- The permit has not been modified.
- The authorization expires after a defined period.

This allows enterprise systems to trust the authorization independently of the AI that requested it.

Operate/Environment variable reference

Environment variable reference#

Reference · Deployment · Security · Repository example file

Parmana is configured through environment variables. The server reads them at start-up and refuses to start when a required one is missing or invalid. The SDKs and the CLI read a few more, listed at the end.

How to read this table.

  • Default is the value used when the variable is unset, as the code defines it.
  • Status: Implemented (in the code and exercised here), Implemented, not exercised here, Experimental (opt-in; marked experimental in the OpenAPI document), or Test only.
  • Where the repository's example file and the code disagree, this table follows the code, and says so.

Server: essentials#

Variable Default Accepted values Required Status Notes
NODE_ENV unset development, test, production No Implemented Only test changes behaviour in a way the code checks for. PARMANA_TEST_APPROVER_PUBLIC_KEY_FILE requires test. Use production in a deployment.
PORT 3000 A port number No Implemented The port the API binds to.
HOST 0.0.0.0 An interface address No Implemented The interface the API binds to.
PARMANA_POLICY_DIR none A directory path Yes Implemented Holds <name>/<version>/policy.json. The server refuses to start without it: PARMANA_POLICY_DIR is not set. (observed).
PARMANA_KEY_DIR none A directory path Yes Implemented Holds the signing key pairs (default, gateway, and others). The server refused to start without it under NODE_ENV=test as well (observed: PARMANA_KEY_DIR is not configured.).
PARMANA_STORAGE memory memory, postgres, supabase No Implemented supabase is an alias for postgres. memory loses all state on restart (observed).
DATABASE_URL none A PostgreSQL connection URL Yes with postgres/supabase Implemented The server refuses to start with PostgreSQL storage without it. The example file also says other stores use it, regardless of storage mode.
DATABASE_PROVIDER none (removed) No Implemented Setting it refuses start: DATABASE_PROVIDER is no longer read; set PARMANA_STORAGE instead.
PARMANA_DB_SCHEMA public A schema name No Implemented Puts this process's tables in another schema of the same database.
SHUTDOWN_TIMEOUT_MS 10000 Milliseconds No Implemented How long a graceful shutdown waits for in-flight requests.
LOG_LEVEL info Any string (not validated) No Implemented Conventionally debug, info, warn or error.

Caller authentication and governance#

Variable Default Accepted values Required Status Notes
PARMANA_API_KEYS none JSON array Yes, unless auth is disabled Implemented Each entry: callerId, keyHash (SHA-256 hex of the raw key), and optionally allowedCapabilities, allowedPrincipalIds, credentialHolderType (USER, SERVICE, ROLE, ORGANIZATION), stepUpPublicKey (PEM). Generate entries with parmana-ops keys generate-api-key.
PARMANA_AUTH_DISABLED false true disables authentication No Implemented Never in a deployment. /ready reports authDisabled: true. Also used by the sandbox options.
POLICY_CHANGE_CHECKERS empty (nobody may approve) JSON object: policy name to an array of caller ids No Implemented Which callers may approve a change to each policy. Empty approves nothing.
PARMANA_TEST_APPROVER_PUBLIC_KEY_FILE none A PEM file path No Test only Trusts a local test approver. The server refuses it unless NODE_ENV=test.
POLICY_GOVERNANCE_INTEGRITY_CHECK_INTERVAL_MS 300000 Milliseconds; 0 or less means start-up only No Implemented How often the server re-checks each live policy file against its approval record (per the example file).
RATE_LIMIT_AUTH_FAILURE_PER_MINUTE 30 Integer No Implemented Failed authentications (401) per IP. Verified: two 401s, then 429, in the examples runner.
RATE_LIMIT_EXECUTE_PER_MINUTE 30 Integer No Implemented POST /execute, per authenticated caller.
RATE_LIMIT_PUBLIC_PER_MINUTE 60 Integer No Implemented Unauthenticated work routes (verification, handbook), per IP.
RATE_LIMIT_HEALTH_PER_MINUTE 300 Integer No Implemented /health and /ready, per IP.

Keys and cryptography#

Variable Default Accepted values Required Status Notes
KEY_PROVIDER local local, aws-kms No Implemented (local); aws-kms checked at start-up The code refuses any other value as not implemented (IMPLEMENTED_KEY_PROVIDERS). aws-kms restricts the primary signature to Ed25519.
PARMANA_SIGNING_KEY_ID default Key id No Implemented The key that signs trust records and approvals.
PARMANA_GATEWAY_KEY_ID gateway Key id No Implemented The gateway's attestation key, in the key directory.
PARMANA_GATEWAY_ID parmana-gateway Letters, digits, ., _, - No Implemented The gateway's logical identity.
PARMANA_VERIFICATION_KEY_ID default Key id No Implemented The key id records are signed with. Change only when rotating.
PARMANA_VERIFICATION_SECONDARY_KEY_ID default-secondary Key id No Implemented The secondary key id for hybrid records.
PARMANA_VERIFIER_KEY_ID signal-verifier Key id No Implemented Signs the verifier's read-only fetches.
PARMANA_KEY_MATERIAL_JSON none JSON No Implemented Key material written into the key directory at boot, for files that do not exist there. Treat as a secret.
PARMANA_KEY_MATERIAL_SECRET none A secret name or ARN No Implemented The same JSON, held in a secrets manager. Needs PARMANA_SECRETS_PROVIDER=aws-secrets-manager.
PARMANA_SECRETS_PROVIDER none aws-secrets-manager No Implemented Where to read PARMANA_KEY_MATERIAL_SECRET.
AWS_REGION, AWS_ROLE_ARN none AWS values With aws-kms or the secrets provider Implemented, not exercised here The server assumes the role with the platform's OIDC token, per the example file.
CRYPTO_MODE single single, hybrid No Implemented hybrid also signs with the secondary provider. Verified with dilithium3.
PRIMARY_SIGNATURE_PROVIDER ed25519 ed25519, ecdsa-p256, dilithium3, dilithium5, sphincs-plus No Implemented (ed25519 exercised) The primary signing algorithm.
SECONDARY_SIGNATURE_PROVIDER none Same list, must differ from the primary Yes with CRYPTO_MODE=hybrid Implemented (dilithium3 exercised) Without it, hybrid execution releases the action and then fails to record it (observed: 500).
HASH_PROVIDER sha256 sha256, sha3-512, blake3 No Implemented Hash algorithm, per the example file.
HYBRID_SIGNATURE_REQUIRED false true No Implemented Requires a hybrid envelope on records.
HYBRID_REQUIRED_FROM none UTC ISO-8601 ending in Z No Implemented Records created at or after this instant must be hybrid-signed.
HYBRID_SCHEMA_VERSION 3 (unset) 2, 3 No Implemented (3 exercised) 3 covers the whole record (see Security).
HYBRID_SCHEMA_V3_ACKNOWLEDGED not read Ignored. Retired when schema 3 became the default (2026-11-20). Remove it from environment files.
TRUST_PROFILE v1 v1 No Implemented The trust record schema profile.
RECEIPT_VERSION 1 Free text (only 1 is meaningful) No Implemented The receipt schema version.
EXECUTION_AUTHORIZATION_TTL_SECONDS 120 Seconds No Implemented How long a signed execution authorization is valid, when the caller does not set one.

Experimental and opt-in#

Variable Default Status Notes
PARMANA_POLICY_V2_DECISIONS off Experimental Mounts the policy v2 decision routes (/v2/...). Read with PARMANA_POLICY_V2_CAPABILITIES, PARMANA_POLICY_V2_SOURCE_URL and PARMANA_POLICY_V2_SOURCE_TOKEN (the source token is required when the URL is set).
PARMANA_POLICY_V2_SNS_EVENTS, PARMANA_POLICY_V2_EVENTS_SECRET off Experimental Event channels for the v2 surface.
EXECUTION_INTENTS_CHECK per the example file Experimental Execution intents (ADR-0012). The example file says it is ignored in production, where the gate is always on.
SIGNING_READINESS_CHECK per the example file Implemented Readiness check of the signing setup. The example file says it is relaxed only under test or development.
KILL_SWITCH_ENABLED false Experimental Mounts the kill-switch routes (ADR-0017). Needs DATABASE_URL. Not mounted in the verified configuration: /kill-switch/status returned a JSON 404 with ROUTE_NOT_FOUND (earlier builds returned an HTML page).
KILL_SWITCH_RESET_NEEDS_SECOND_OPERATOR per the example file (true in production) Experimental A reset needs two different operators.
INBOUND_AUDIENCE off Experimental Enables the inbound refund decision routes (RFC-0025). The server refuses to start without the gateway's private key.
ALERT_WEBHOOK_URL, ALERT_WEBHOOK_SECRET none Implemented, delivery not exercised here An alert webhook and its signing secret.
PARMANA_SKIP_DOTENV unset Implemented 1 stops the loaders from reading a .env file. The test suite sets it.

Test and example variables#

Variable Used by Status Notes
TEST_DATABASE_URL Integration tests Test only Must differ from DATABASE_URL. The tests refuse hosted databases unless listed in PARMANA_TEST_PROJECT_REFS and ALLOW_LIVE_SUPABASE=1.
PARMANA_ALLOW_UNGOVERNED_POLICY Was set by the examples runner, the load test and tutorial 81 Removed Retired and removed. It was set by the examples runner, the load test and one tutorial, but no server code read it. Governance is enforced in every environment; the version in effect comes only from an approval record. Remove it from any environment file.
PARMANA_PRODUCTION_PROJECT_REFS, PARMANA_TEST_PROJECT_REFS, ALLOW_LIVE_SUPABASE Test-database guard Test only Guard rails so tests never reach a production database.
GOVERNED_CONFIG_DIR, GOVERNED_POLICY_VERSION, PARMANA_ENDPOINT This portal's examples Example only Read by the scripts in docs/developer-portal/examples/.

SDK, CLI and client variables#

These are read by the client tools, not by the server.

Variable Read by Meaning
PARMANA_TOKEN parmana-ops The caller's bearer token. Read from the environment only.
PARMANA_API_URL parmana-ops The API address. A --api-url flag overrides it.
PARMANA_PROFILE parmana-ops A named API address from the config file.
PARMANA_CONFIG parmana-ops Path to the CLI config file.

The TypeScript and Python SDKs take the endpoint and key as constructor arguments. They do not read these variables themselves. Read the key from your own environment, as the examples do.

Script, test and tooling variables#

These are read by the repository's scripts and tests, not by the server or the SDKs. They are listed so that the reference is complete.

Variable Read by Meaning
PARMANA_API_KEY scripts/list-approval-refusals.mjs A caller key for the script's read-only listing. Not read by the SDKs.
PARMANA_BASE_URL scripts/list-approval-refusals.mjs The API address for that script. Default http://localhost:3000.
PROPOSER_KEY, REVIEWER_KEY scripts/refresh-approved-policy-content.ts, scripts/local-review-action.ts The maker's and checker's keys for the one-shot governance scripts. Tutorial 117 describes them.
AWS_PROFILE scripts/verify-kms-signing.ts The AWS profile for the KMS check (npm run verify:kms). The standard AWS chain applies otherwise.
CI_DATABASE_URL Continuous integration A database for CI runs. Not used by the server.
CONTROL_PORT, LISTEN_PORT, TARGET_PORT Load and proxy test scripts Ports for test harnesses.
VITEST, STRYKER_REPORT_NAME Test and mutation tooling Set by the test runners.

Variables the example file lists that were not checked#

The repository's example file documents more variables than this table. Each one in the table above was matched to the code. Variables that appear in the example file but not in this table were not checked against the code in this verification, and should be read there with that caveat.

Minimum set for a deployment#

bash
NODE_ENV=production
PARMANA_STORAGE=postgres
DATABASE_URL=postgresql://…                      # a secret
PARMANA_POLICY_DIR=/srv/parmana/policies
PARMANA_KEY_DIR=/srv/parmana/keys                # or KEY_PROVIDER=aws-kms with its settings
PARMANA_API_KEYS='[{"callerId":"…","keyHash":"…","allowedCapabilities":["…"]}]'
POLICY_CHANGE_CHECKERS='{"vendor-payment":["…"]}'
CRYPTO_MODE=hybrid
SECONDARY_SIGNATURE_PROVIDER=dilithium3
# HYBRID_SCHEMA_VERSION defaults to 3. Set 2 only to roll back.

This is an illustrative set. The values are placeholders. Check each one against your deployment before you use it.

Operate/Error code catalogue

Error code catalogue#

Reference · Full code index (106 codes, generated) · Troubleshooting · API overview

A Parmana error is an HTTP status plus a body. The body has an error message and, for most refusals, a code. The SDKs turn the status into a class, and keep the server's code where one is sent.

This page lists the codes a developer meets most often. Each row says whether the code was observed in this verification (the status and message are real), or from source/spec (the code and status are in the OpenAPI document or the server source, and the row says where). The generated index lists every code the server source defines, with the file that raises it.

Status to SDK class#

Status TypeScript class Python class Notes
400 ValidationError ValidationError Malformed request. Nothing was stored.
401 AuthenticationError AuthenticationError No key, or an unknown key.
403 AuthorizationError, or ExecutionRejectedError for POLICY_DENIED AuthorizationError, or ExecutionRejectedError CAPABILITY_NOT_ALLOWED and TENANT_NOT_ALLOWED keep their code as serverCode.
404 NotFoundError NotFoundError
409 ConflictError ConflictError
202 ExecutionPendingError (on execute) ExecutionPendingError Released; the status is not yet final.
429 RateLimitError RateLimitError retryAfterSeconds when Retry-After is sent.
5xx InternalServerError InternalServerError The server code is kept as serverCode.
none NetworkError, TimeoutError NetworkError, TimeoutError

The mapping is in typescript/src/transport/mapHttpErrorResponse.ts and in the Python errors package.

Codes observed in this verification#

Code Status Where it comes from Message (as observed) Meaning and fix
CAPABILITY_NOT_ALLOWED 403 Caller check on POST /execute Caller is not permitted to invoke this capability. The key may not invoke this action. Check GET /callers/me.
CAPABILITY_NOT_BOUND 404 GET /policies/in-effect No policy is bound to capability "…". The capability has no policy binding on this build. Name the policy in the request instead.
VERIFICATION_FAILED 404 POST /verify, POST /receipt Execution Trust Record not found. The key has no record with that id. Check the id and the key.
SAME_ACTOR_CANNOT_APPROVE_OWN_CHANGE 403 POST /policies/pending-changes/{id}/approve …was proposed by this same caller — the proposer (maker) may not also approve or reject it (checker). The maker tried to approve their own change. A different checker approves.
NON_HUMAN_CALLER_DENIED 403 Governance routes NON_HUMAN_CALLER_DENIED (code) A service caller tried a human-only route.
STEP_UP_AUTHORIZATION_INVALID 403 Governance approve and reject (code) The envelope is missing, expired, wrong, or not signed by the checker's registered key. Sign a fresh envelope and submit it at once.
SOURCE_UNAVAILABLE Not captured (the runner reported a business-validation outcome) A sourced fact business validation SOURCE_UNAVAILABLE: … payment provider timed out The source did not answer. Parmana fails closed. Do not approve on a guess.
RATE_LIMITED 429 Rate limits 429 RATE_LIMITED with Retry-After 60 Too many requests, or too many failed authentications. Wait for Retry-After.

Plain error bodies without a code are also common. Each row below was observed unless it says "from source":

Status Body (observed) Meaning
401 {"error":"authentication required"} No key, or an unknown key.
400 {"error":"businessTransactionId must be a valid UUID."} The id is not a UUID.
400 {"error":"capability is required, for example ?capability=erp:invoice-pay."} A required query parameter is missing.
403 {"error":"Caller is not permitted to assert this authority.principalId."} (from source, not triggered here) The key may not act for this principal. No code.
403 {"error":"Execution rejected: Rejected: …"} An execution refused by the decision. The message names the reason.
404 {"error":"Business Transaction not found."} Unknown transaction for this key.
404 {"error":"Execution Trust Record not found."} Unknown record.
404 {"error":"Policy 'vendor-payment' version '2.1.0' was not found."} No such version on this server.
409 {"error":"Business Transaction '…' already exists."} The id was used. Nothing ran again.
400 {"error":"Request body must be a Refusal Record (refusalRecordId, …)."} A verification body is missing fields. The message names them.
404 {"error":"Route not found.","code":"ROUTE_NOT_FOUND"} An unknown path, sent with a valid key. Added in this change; earlier builds returned an HTML page.

Execution refusals#

A refused execution comes back as 403 with a message that begins Execution rejected:. The message is the reason. The observed reasons:

Reason (observed) Cause
Rejected: policy "vendor-payment"@"2.1.0" has no PolicyChangeApprovalRecord -- it has never completed the Policy Governance approval flow. The version was never approved through maker-checker.
Rejected: policy "vendor-payment"@"2.1.0" was superseded: the version in effect is "2.1.1", the one most recently approved. The request named an older version.
Rejected: declared signal(s) do not match independently verified state (humanApproved=true != verified humanApproved=false). The verified human approval is false: expired, wrong target or amount, or not trusted.
Rejected: declared signal(s) do not match the executed intent (paymentAmount=999 != intent.parameters.amount=1000). A bound signal differs from the request.
Rejected: no approval verifier is configured, so the signed human approval this action needs cannot be checked. The server has no approval verifier configured (tutorial 120).
Vendor payment rejected because the assessed payment risk exceeds the maximum permitted threshold. A policy rule rejected the request.
Vendor payment rejected because one or more required policy conditions were not satisfied. A required condition is not met, for example no approval attached.

Codes from source and the OpenAPI document#

These were not triggered by a live server run. Each is described from the OpenAPI document (openapi/openapi.yaml) or the server source. Where an automated test in the server's suite triggers the branch, the row names that test. The status is the one the document states.

Code Status Meaning Action
POLICY_DENIED 403 The policy refused the request. Final for that request. Show the reason. Do not retry.
EXECUTION_RECORD_INCOMPLETE 500 The action was released, but its signed record could not be produced. The OpenAPI document says not to retry as a new transaction. Triggered over HTTP by packages/api/tests/integration/execution-record-incomplete-http.integration.test.ts (the response has the code and the transaction id, and the connector ran once). Reconcile the transaction.
EXECUTION_OUTCOME_UNKNOWN 502 The action was released and the connector call failed. Triggered over HTTP by packages/api/tests/integration/execution-failure.integration.test.ts. Reconcile against the connector. Do not resend as new.
SIGNING_UNAVAILABLE 503 Signing is unavailable. The source describes it as "nothing executed". Retry later with the same id.
TENANT_NOT_ALLOWED 403 The key may not act for this tenantId. Use an allowed tenant, or omit it.
AUDIT_UNAVAILABLE 503 (in the audit path) The caller audit trail could not be written, so the request is refused rather than run unrecorded. Check the database.
EXECUTION_STATUS_PENDING 202 Released and recorded, status EXECUTING. Triggered on PostgreSQL by packages/api/tests/integration/transaction-status-postgres.integration.test.ts (the EXECUTED write fails after the release). Reconcile.
NO_APPROVAL_RECORD 403 at execution (observed as the refusal "has no PolicyChangeApprovalRecord") A policy version has no approval record. Approve the version through maker-checker.

The full list of codes the server defines, with the file that raises each, is in the generated index. Many of them are for features that are opt-in or experimental: execution intents (EXECUTION_INTENT_*), the kill switch (KILL_SWITCH_*), inbound refunds, the policy v2 review and replay flow (REVIEW_*, THRESHOLD_*), and connector changes. Those are described in the API overview.

HTTP status summary#

Status Typical codes First check
200 none Read the body. For verify and replay, read status or verified, not the status alone.
201 none A proposal or declaration was accepted.
202 EXECUTION_STATUS_PENDING Reconcile. Do not resubmit.
400 none (message names the field) Fix the request.
401 none Check the key.
403 POLICY_DENIED, CAPABILITY_NOT_ALLOWED, TENANT_NOT_ALLOWED, SAME_ACTOR_CANNOT_APPROVE_OWN_CHANGE, NON_HUMAN_CALLER_DENIED, STEP_UP_AUTHORIZATION_INVALID Read the message and the code.
404 CAPABILITY_NOT_BOUND Check the id, the policy version, and the binding.
409 none The id was used. Read the existing outcome.
429 RATE_LIMITED Wait for Retry-After.
500 EXECUTION_RECORD_INCOMPLETE The action may have run. Reconcile.
502 EXECUTION_OUTCOME_UNKNOWN The action may have run. Reconcile.
503 SIGNING_UNAVAILABLE, AUDIT_UNAVAILABLE Nothing was executed. Retry later.

For the debugging steps that go with each row, see Troubleshooting.

## Exact entry text

**G-111. The HubSpot verification helper approves its own fetch.** `executeHubSpotCapability` builds an authorization with a random decision id and `decisionOutcome: "APPROVED"`, and signs it. There is no runtime decision behind it. Fix (containment, not removal): the fetch is signed with a dedicated verifier key (`PARMANA_VERIFIER_KEY_ID`, default `signal-verifier`), and the gateway accepts that key only for `hubspot:deal-fetch` (`verificationOnlyKeys`). A compromised verifier key can therefore read a deal but cannot release a write; the audit reproduces the refusal. Status: in progress (2026-10-28). The deal read now needs its own signed approval, checked before the fetch, so the helper no longer approves its own read. The change is on branch `fix/hubspot-self-approval` and is not merged. It is held until a new `hubspot-deal-update` policy version declares the read approval signal, because production would refuse every update before then. Until it ships, the `ccr-6f1b8d3b-o5pqwj` containment above is the only control.

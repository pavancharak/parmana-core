## Exact entry text

**G-122. Parmana has no operator kill switch, and no fresh check that a stop is in force.** The only stop controls are a policy version that refuses, revoking a connector or approver, and removing an agent's key. The key removal takes effect only on restart or redeploy. An action already released is not recalled. Regulators' draft guidance asks that a system can be suspended at once, and that the switch is verified on an ongoing basis. A signed refusal proves a refusal happened, not that the switch works now. Status: open, partly closed. Live in production since 2026-10-20 with the switch not tripped: the durable Postgres store, two-person reset (`KILL_SWITCH_RESET_NEEDS_SECOND_OPERATOR=true`), the probe endpoint with stored results, and the guard on execution and approvals are deployed. A check with a valid key returns `active: false` with the nonce echoed and `signed: false`. Claim: CLAIMS 2.58, with what is verified and what is not claimed. Operations: [docs/internal/runbooks/KILL-SWITCH-OPERATIONS.md](runbooks/KILL-SWITCH-OPERATIONS.md). Decided 2026-10-20: every probe row is kept (no deletion job); the probe runs from a scheduled GitHub Actions workflow on `main`, every 15 minutes since 2026-10-20; status and audit events stay unsigned until a build-bound signing key exists (G-118). Release check added: an action that passed the HTTP guard is checked again just before it is released to a connector (`killSwitchReleaseHook`, `KillSwitchActiveError`, 503 `KILL_SWITCH_ACTIVE`, nothing executed), so a trip that lands after the guard refuses the release. Tested by `packages/api/tests/integration/kill-switch-release-window.integration.test.ts` and `packages/runtime/tests/integration/kill-switch-release.integration.test.ts`. Narrowed, not closed: the check and the connector call are separate steps, so a trip in the gap between them can still release that one action. On 2026-10-24 the scheduled probe workflow had failed on each of its last five runs, its first step failing when `PARMANA_PROBE_KEY` is not set; that secret's presence was not confirmed. Operator B deviation, 2026-10-24: the live key list has a stand-in entry for `operator-b` with no capabilities (a key generated without `--allowed-capabilities`, whose printed key was discarded). It exists only so the scheduled probe can be added to the list without dropping a caller. It cannot trip, reset or probe, so a two-person reset still needs a second real operator. Swap in the real `operator-b` entry, with `kill-switch:reset`, when that person is available, then redeploy and re-run the probe. Recorded in the credential ceremony runbook, section 8. Still open: the third-party check is not built; the two-person reset has not yet been exercised with two real keys. The kill switch OpenAPI examples were captured from the routes in a test run. Decisions: reset needs two people in production; operator credentials are named and individual; probe history is kept at least one year; no per-agent halt in the first build; the halt also blocks approval endpoints. Review requirements: trip, reset, status and probe stay reachable while the switch is on; fail closed on a read error; separate `kill-switch:trip`, `kill-switch:reset` and `kill-switch:probe` capabilities; the third-party check runs on a non-production deployment only; status is signed by a build-bound key only once G-118 is fixed; the probe runs from an external scheduler, because Vercel Hobby allows one cron run a day; trip and reset run in a database transaction.

**Status (from the entry, recorded 2026-11-04):** open, partly closed.

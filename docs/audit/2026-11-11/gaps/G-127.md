## Exact entry text

**G-127. A revoked caller API key stayed valid until the server restarted.** Caller keys were loaded once at startup (`packages/api/src/bootstrap/createCallerAuthenticator.ts`), so removing a key from `PARMANA_API_KEYS` took effect only at restart. Status: fixed in code, not yet live. The fix is in PR #238, merged as `fba4b2c`: `StaticKeyAuthenticator` checks `caller_key_revocations` on every request, and a failed lookup refuses the key. Production still runs build `b1e12d7`, which predates the fix. The gap closes when a build of `fba4b2c` is Ready and the checks in `docs/internal/runbooks/CALLER-KEY-REVOCATION.md` pass. Tests: `packages/api/tests/unit/auth/static-key-authenticator.test.ts` (revocation cases, including a store failure refusing the key) and `packages/api/tests/unit/bootstrap/create-caller-authenticator.test.ts`. The Supabase repository has a live-database suite, `packages/storage/tests/integration/postgres-caller-key-revocation-repository.integration.test.ts`. It runs only against a local or declared disposable database, and it has not been run against one yet. Process: no linked issue; no ChallengeRecord, because the change fixes a gap and does not challenge an existing claim (RFC-0022). Claim: CLAIMS 2.16.

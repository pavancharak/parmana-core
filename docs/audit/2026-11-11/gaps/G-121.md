**G-121. Verifiers outside this repository read only schema version 2.** The public verifier 0.3.0 reads schema version 3 and the cutover. The separately published verifier and both SDKs read version 2 only, and report ML-DSA-65 records as not valid. A schema version 3 record is therefore unreadable by those consumers. Status: open, gates schema version 3 issuance. ## Status note, 2026-11-15

Checked against the published packages, not only the source. The published `@parmana/sdk@2.0.2` (npm) and `parmana@2.0.1` (PyPI) both verify a schema version 3 hybrid record from parmana-core at `7e9a54fb`, and both reject the same record after `updatedAt` is changed. Both also accept schema version 2 and single-algorithm records by default. So the statement in the entry above, that the SDKs read version 2 only, is not true of the published SDKs. Their offline verifiers accept version 3.

Still open under this gap: the separately published verifier has not been checked (`parmana-verifier` PR #39 is not merged, and the published version of `@parmana/verifier` was not read). The owner decision to set `HYBRID_SCHEMA_VERSION=3` by default depends on that check. Evidence: the results entry of 2026-11-15 in `docs/ASSURANCE_RESULTS.md`.

## Follow-up, 2026-11-15: default changed to v3

The owner chose v3 as the default. The change is on `claude/default-schema-v3` in parmana-core (a PR, not merged). Unset `HYBRID_SCHEMA_VERSION` now means 3. `2` is still accepted. The acknowledgement gate (`HYBRID_SCHEMA_V3_ACKNOWLEDGED`) is removed, because the condition it guarded is met. It takes effect only in `CRYPTO_MODE=hybrid`, and hybrid is not live on any deployment (G-119).

## Correction, 2026-11-15: which verifier the entry means

The closure note above says "0.3.0 is not a published version of either package". That is wrong for npm. `@parmana/verifier` 0.3.0 was published on 2026-10-19 (see the verifier's CHANGELOG). Read from source, without running it, every published verifier version checked accepts schema version 3:

- `@parmana/verifier` 0.3.0 (npm): `SUPPORTED_SCHEMA_VERSIONS = [2, 3]`, whole-record message for version 3.
- `parmana-verifier` 1.6.3 (PyPI): `SUPPORTED_SCHEMA_VERSIONS = (2, 3)`.
- `parmana-verifier` 0.1.0 (PyPI): `WHOLE_RECORD_SCHEMA_VERSION = 3` is defined.
- `@parmana/verifier` 2.0.1 and `parmana-verifier` 2.0.1: run, as recorded above.

So the statement in G-121 that verifiers read only schema version 2 is not true of any published verifier version checked. Versions older than the ones listed, and the SDK releases before 2.0.1, were not checked. The owner should decide whether G-121 is closed as "the claim did not match the published packages", and whether the older SDK releases need a check.

## Final status, 2026-11-15: closed

**CLOSED. Reason: the claim did not match the published verifiers.** Every published verifier checked reads schema version 3: `@parmana/verifier` 0.3.0, 2.0.1, `parmana-verifier` 0.1.0, 1.6.3, 2.0.1. Versions older than those listed, and SDK releases before 2.0.1, were not checked. A new gap is needed if any of them is found to read v2 only.

Checked against the published packages, not only the source. The published `@parmana/sdk@2.0.2` (npm) and `parmana@2.0.1` (PyPI) both verify a schema version 3 hybrid record from parmana-core at `7e9a54fb`, and both reject the same record after `updatedAt` is changed. Their offline verifiers accept version 3.

## Closed, 2026-11-15

**Status: closed.** Both published verifiers and both published SDKs read schema version 3, and each verifies a v3 hybrid record from parmana-core at `7e9a54fb` as valid with `coverage: full`. Each refuses the schema version 2 and single-algorithm records by default, which is the intended policy.

Evidence, observed in the session (results entry of 2026-11-15, second run):

- `@parmana/verifier` 2.0.1 (npm), CLI: v3 valid, `coverage: full`, exit 0. v2 and single-algorithm refused by default, exit 1.
- `parmana-verifier` 2.0.1 (PyPI), CLI run from the extracted wheel in isolated mode: the same three results.
- `@parmana/sdk` 2.0.2 (npm) and `parmana` 2.0.1 (PyPI), offline verifier: v3 valid; a v3 record with `updatedAt` changed refused (earlier run, same date).

The entry's "separately published verifier" is taken to mean these two packages. The entry names "public verifier 0.3.0", which is not a published version of either package. The owner should confirm that the two packages are the ones this gap meant. If it meant another package, this closure does not cover it.

Closing G-121 does not set schema version 3 as the default. That is a separate change, and the owner decides when it ships.

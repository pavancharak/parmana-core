## Exact entry text

**G-147. A policy decision has no insufficient-evidence outcome: missing signals evaluate as false (R5).** In `packages/policy/src/PolicyEngine.ts`, a leaf whose signal is undefined evaluates to false (`evaluateCondition`). `toOutcome` maps APPROVE to APPROVE and every other action to REJECT. When no rule matches, the reason is `no_rule_matched` and the outcome is REJECT. A reader of the record cannot tell absent evidence from a real refusal. Status: closed. Decided 2026-11-07: a request that omits a fact the decision depends on is refused as REJECT, with a reason that names the missing facts (PR #483, G-157). No separate insufficient-evidence outcome, so no change to the client contract. Closing it needs a distinct insufficient-evidence result that names the missing facts, carried into the Refusal Record. Process: linked issue #451. Claim: CLAIMS 2.2 and 2.3. **Update 2026-11-07:** partly closed. A request that omits a fact a rule depends on is now refused with `matchedRuleId: "missing-fact"`, and the reason names the missing facts, so an absent fact no longer falls through to a later rule (G-157). The outcome is still REJECT, not a distinct insufficient-evidence result, so the outcome design stays open.

## Dated note, 2026-11-24

Every policy verdict now carries an `evidence` field, distinct from `outcome`:

- `{ status: "sufficient" }`: every fact the evaluation read was present with its declared type.
- `{ status: "insufficient", missingFacts }`: a needed fact was not sent. `missingFacts` lists each one once, sorted.
- `{ status: "invalid", invalidFacts }`: a fact was sent with a type the policy does not declare.

The outcome stays `REJECT` for all three, so the client contract is unchanged. The field is copied onto the recorded `Decision` (`packages/shared/src/domain/decision.ts`). The runtime's own refusals carry it too: the approval-verifier gate reports `insufficient` evidence, because the signed approval could not be checked.

Tests: `packages/policy/tests/unit/PolicyEngine.determination.test.ts` and `packages/runtime/tests/unit/DecisionBuilder.test.ts`.

Not closed by this note: the gateway still returns the same `signalsStillCurrent: false` for a missing signal hash and for a hash mismatch. It does not yet distinguish them, so the release-time check is not an insufficient-evidence determination end to end. This note covers the policy and decision layer only. The owner decides when the claim is closed.

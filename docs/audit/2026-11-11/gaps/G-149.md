## Exact entry text

**G-149. Authorizations with no signals hash skip the release-time signal and approval checks.** `ExecutionGateway.verify` runs the signal verifier only when the authorization carries a `signalsHash`. Without one, `signalsStillCurrent` stays undefined, and `priorChecksPassed` treats undefined as a pass. `RuntimeEngine.execute` now always signs a `signalsHash`, so only authorizations signed before that check existed are affected. Those authorizations passed the approval check at decision time, but nothing re-checks the approval at release. Status: closed. `ExecutionGateway.verify` refuses at release an authorization with no `signalsHash` when the signal state verifier is wired. The release check's result is `signalsStillCurrent: false`, so the request fails and nothing is executed. Before this, an absent check was a pass. RuntimeEngine signs a hash on every authorization it issues now, so only an authorization issued before that check existed is refused. Tests: `packages/execution-gateway/tests/unit/signal-freshness.test.ts` and `release-approvals.test.ts` (both updated to expect the refusal). Process: linked issue #453.

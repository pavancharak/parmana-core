## Exact entry text

**G-124. The server trusted certificates from eMudhra's compromised intermediate CA keys.** Found 2026-10-23. In October 2026 eight eMudhra intermediate CA keys were found to be weak, so anyone who recovered them could issue certificates that chain to eMudhra's emSign roots. Browsers blocked them between 17 and 20 October. Node's TLS stack checks no revocation and rejects those chains only from 22.23.4, 24.22.1 and 26.12.1 (21 October). The hosted API ran Node 24.21.0 (logged by the runtime line added in parmana-core#36), and the Docker image's base was Node 24.22.0, so every outbound call (connectors, connector endpoints, the database, the key service) would have accepted such a certificate from anyone able to intercept it. No use of the keys is known (CERT-In advisory CIAD-2026-0050). **Fixed 2026-10-23:** both entry points remove the four emSign roots from the process's default CA list at startup, before any outbound connection, matched by SHA-256 fingerprint (`packages/api/src/bootstrap/distrustCompromisedRoots.ts`, parmana-core#39), and the Docker base images are re-pinned to Node 24.22.1 (parmana-core#19). Production confirmed it: the runtime line reads `"node":"v24.21.0"` and `"distrustedRootsRemoved":4`. The image `ghcr.io/pavancharak/parmana-api:server-v1.0.1` (digest `sha256:7e17dfb8e1e5e391cc0acd0a2a19801d1b1b888b529ee75a977846c219dce97c`) carries both, with SLSA provenance. Cost: a server whose certificate chains to an emSign root cannot be reached; none of the systems the server calls uses one. Claim: CLAIMS 3.27. Status: fixed 2026-10-23.

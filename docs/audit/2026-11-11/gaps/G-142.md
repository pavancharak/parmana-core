## Exact entry text

**G-142. The inbound check did not evaluate the capability's policy. Resolved.** `POST /v1/inbound/checks` (claim 3.30) applies the partner's grant limits only. The policy for the capability is not evaluated, so an approval from the check is not a policy decision. The runtime's `decide()` step (claim 3.32) can evaluate a policy without executing, but the check does not call it. Status: resolved. Merged to `main` in pull request #448 (merge commit `aae3c25`, code commit `bc5491f`). The check now runs the policy bound to the capability through the runtime's decide step, with the same verification and binding checks as /execute, and approves only when the policy and the grant both allow. A capability with no bound policy is refused (`no_policy_bound`). Claim 3.30 and the public page describe the new behaviour. Process: from pull request #448; no GitHub issue.

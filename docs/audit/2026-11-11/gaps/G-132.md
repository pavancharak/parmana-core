## Exact entry text

**G-132. A repeated release was refused with 403, not answered with its first result.** parmana-core's reference (`typescript/src/crypto/release.ts`, ADR-0013) expects the endpoint to answer a repeated release with its first stored result. Any answer other than 200 is a failure to parmana-core, so a retry after a timeout was recorded as failed. The action was not run twice. Status: fixed and merged in parmana-connect PR #32 on 2026-11-05 (head `33374c6`); issue #34 closed. A ledger now stores each release's answer. The first request claims the id and runs the action. A repeat gets the stored answer with 200, and a request that arrives during the first run gets 409. Known limit: if the process stops after the action runs and before the answer is stored, that id stays unanswered and a repeat gets 409 until an operator resolves it. Nothing runs twice. Tests: `tests/release-ledger.test.ts`, including the Postgres ledger against PostgreSQL 16. README, "How external systems connect", was updated to match: a repeated release now gets the first answer.

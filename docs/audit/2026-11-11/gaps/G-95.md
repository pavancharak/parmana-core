## Exact entry text

**G-95. The Policy Governance integrity check at startup could not stop a server from starting on a mismatch.** `verifyPolicyGovernanceIntegrityAtStartup()` ran after `app.listen()` without being awaited, and returned `{ checked: 0, mismatches: [] }` when the approval records could not be listed. So a live policy file edited outside the pending-change API, or a database outage at boot, left the server serving under a policy nobody could show was approved. Decision (2026-10-15, agreed by the maintainer): block startup in both cases. Fix: `assertPolicyGovernanceIntegrityAtStartup()` throws on a mismatch or an unrunnable check, and `server.ts` awaits it before `app.listen()`; the process exits with status 1 and logs `policy_governance_integrity_startup_refused`. The periodic re-run stays fail-open. Tests: `packages/api/tests/unit/verifyPolicyGovernanceIntegrityAtStartup.test.ts` (three new startup cases). Status: reported fixed on branch `claude/startup-integrity-block`, which is no longer in the repository, so whether this reached `main` is not verified. Known cost: a database outage at boot now stops the server until the database is reachable.

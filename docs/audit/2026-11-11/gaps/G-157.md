## Exact entry text

**G-157. A request that omitted a fact could be approved by a later rule (partly closes G-147).** `PolicyEngine.evaluate` treated an absent fact as false for its own condition only. A reject rule that read the absent fact was skipped, and a later approve rule could match. Example: a policy that rejects when `risk_score` exceeds 70 and approves when `currency` is `INR` approved an INR request with no `risk_score`. Status: fixed in parmana-core PR #483 (open). The engine evaluates each condition in three values. A rule whose outcome depends on an absent fact stops evaluation and returns REJECT with `matchedRuleId: "missing-fact"`, and the reason names the missing facts. A rule that matches, or that does not read the absent fact, is decided as before. The check is narrower than "refuse any omitted fact": that version would refuse `crm:read` requests under the shipped `connector-capability` 1.1.0 policy, which never reads `paymentAmount` for that capability. Tests: `packages/policy/tests/unit/PolicyEngine.missing-fact.test.ts`, with updated expectations in `CustomerRefundPolicy110.test.ts`, `CustomerRefundPolicy120.test.ts`, `signalTypes.test.ts` and `packages/runtime/tests/unit/DecisionBuilder.test.ts`. Claim: CLAIMS 2.3.

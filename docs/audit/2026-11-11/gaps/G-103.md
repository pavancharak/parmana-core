## Exact entry text

**G-103. A signed authorization released for a denied decision.** The gateway verified the signature, expiry, content hash, policy hash and signals, but never read the decision outcome, and the signed payload held only the decision id. A holder of the signing key, or any code outside the runtime gate, could obtain a valid authorization for a denied decision and have it released. The proof audit reproduced the release. Fix: the runtime signs `decisionOutcome: "APPROVED"` into the authorization after `ExecutionGate.enforce`, and the gateway refuses any authorization without that value (`decisionApproved` check). A control with an identical payload signed as APPROVED still releases. Status: fixed on branch `ccr-6f1b8d3b-o5pqwj` (commit ddb6009); that branch and commit are no longer in the repository, so whether this reached `main` is not verified. Residual: the HubSpot helper that signs its own fetch asserts `APPROVED` itself (G-111).

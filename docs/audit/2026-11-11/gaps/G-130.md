## Exact entry text

**G-130. The bearer path to the connector is open unless `PARMANA_RELEASE_ONLY` is set.** The connector accepts a bearer token plus a signed authorization as well as a signed release from parmana-core. The bearer path skips the release checks, so it is a second route to the connector. `PARMANA_RELEASE_ONLY=true` refuses it with 403. The setting defaults to `false`, so existing deployments keep the bearer path. Status: fixed and merged to parmana-connect `main` in PR #32 on 2026-11-05. Not deployed: the Render service still accepts the bearer path until the code is redeployed and the setting is turned on. Tests: `tests/release-only.test.ts`. Process: no linked issue; tracked in parmana-connect PR #32. Claim: README, "How external systems connect", the rule that a connector runs only an approved, signed action.

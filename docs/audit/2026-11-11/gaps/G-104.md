## Exact entry text

**G-104. The in-process release service trusted the caller's verification flags.** `ExecutionControlService.execute` released to a connector on the caller's `verifiedTransaction` booleans, and did not re-verify the authorization. Anyone holding the gateway attestation key, which lives in the same process, could release an unsigned authorization. Fix: the service takes a required `verifyRelease` check (`packages/api/src/bootstrap/createReleaseVerifier.ts`) that re-verifies the signature, expiry, outcome and content hash, and resolves keys through the gateway's own key provider. The nonce is now consumed at that same single release point, on the same store the gateway uses, so a replay through the in-process path is refused (the proof audit reproduces it). Status: fixed on branch `ccr-6f1b8d3b-o5pqwj`; that branch and commit are no longer in the repository, so whether this reached `main` is not verified. Residual: the attestation key itself still lives in the process that can call the control (G-118).

## Exact entry text

**G-148. Decisions do not name the comparison method or version behind the verdict (R3).** `PolicyEngine.evaluate` returns `policyId`, `policyVersion`, `outcome`, `reason`, `matchedRuleId`, `evaluatedRules` and `matchedPath`. None of these identifies the evaluation method or its version. The inputs are hashed into the authorization as `signalsHash`, but they are not stored with the verdict in a form a third party can re-run. Status: closed (on main; method version 2 in PR #483). Each decision now records the method that produced it and that method's version, `evaluationMethod: { id: "deterministic-rules", version: "1" }` (`POLICY_EVALUATION_METHOD` in `packages/policy`, set by `DecisionBuilder`, tested in `packages/runtime/tests/unit/DecisionBuilder.test.ts`). The inputs are already recorded with the verdict as `signals`, so a third party can re-run the evaluation. Decisions recorded before this field existed have no method, and say so by its absence. Process: linked issue #452. **Update 2026-11-07:** the method version is now `"2"` (PR #483), because verdicts change for requests that omit a fact. A `"1"` verdict for such a request can replay to a different result (G-160).

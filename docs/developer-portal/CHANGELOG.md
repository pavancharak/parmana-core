# Changelog

[Portal home](README.md) · [Coverage report](COVERAGE.md)

This changelog records changes to the developer portal in `docs/developer-portal/`. It does not record changes to the Parmana software. For those, see the repository's release notes and the packages' own changelogs (for example `parmana-verifier`'s `CHANGELOG.md`).

Versions follow the packages the portal documents: SDKs and server 4.1.1, offline verifier 2.0.3.

## 2026-11-20: third pass: the review items with a non-breaking fix

Applied the fixes the review asked for that do not change existing behaviour. Each has a test.

- **Python SDK:** `client.server_version()` asks the server for its version, as the TypeScript `version()` does. `client.version` stays the SDK version. (FINDINGS F4)
- **Both SDKs:** the offline trust-record check takes an opt-in `requireFullCoverage` (TypeScript) or `require_full_coverage=True` (Python). It fails closed on legacy (schema 2) records. The default result is unchanged. (FINDINGS F2)
- **Python samples:** the generated Policy v2 samples run their request only under `__main__`. Pytest collects files named `*_test.py`, and an import-time request reached the network during collection.
- **Portal checker:** counts SDK methods from padded table rows too. Before this, the count depended on how the index was last formatted.
- **Cleanup:** removed two empty, unreferenced fixtures (`typescript/test/fixtures/policy.ts` and `replay-result.ts`).

Still open, and needing an owner decision or a release: the schema 2 default (F1), the approval helper for the quickstart (F7), and publishing the `parmana-ops` entry-point fix (the published 4.1.1 still has the old check).

## 2026-11-20: second pass: the five unverified items

Closed the five gaps the first pass left open: Policy v2 in the contract, the exercised features, the connector release path, the untriggered error branches, and the retired flag. Each change has a test or a run named in [COVERAGE.md](COVERAGE.md#verification-log).

Code and contract changes:

- The 28 Policy v2 operations (`/v2/decisions`, `/v2/register/*`, `/v2/reviews/*`, `/v2/evidence/*`, `/v2/console/*`, `/v2/notifications/*`) are in the OpenAPI document, tagged _Policy v2 (experimental)_ and marked `x-stability: experimental`. Their cURL, TypeScript and Python samples are generated by `scripts/openapi/generate-policy-v2-samples.ts`, which `npm run openapi` runs.
- The route-parity test mounts the Policy v2 routes, so the document and the server are compared for them too.
- A new HTTP test pins the `500 EXECUTION_RECORD_INCOMPLETE` branch: the action runs once, and the response has the code and the transaction id.
- Tutorial 81 states the environment it needs. Its README command failed without it.
- The retired `PARMANA_ALLOW_UNGOVERNED_POLICY` is removed from the Docker workflow and the outage drill. Its unit test now asserts that the flag has no effect.

Portal changes: the Policy v2 statements that said "not in the OpenAPI document" were corrected. The error-code total is 106 (it was written as 105). The error-code rows for `202`, `500` and `502` name the test that triggers each one. The coverage report's untriggered list now records what was exercised, with the database-gated suites run against a local PostgreSQL 16.15 cluster.

Open, and new: the Policy v2 document format (F15), the open register response schemas (F16), and no live policy v2 server run (F17). The Docker stack and cloud deployment are still not run (F8).

## 2026-11-20: production-readiness pass on the code and the portal

Changed the code where the review had a verified defect, and corrected the portal to match. Every change has a test or a live check named in [COVERAGE.md](COVERAGE.md#known-issues-found-during-this-review). Items that need an owner's decision are in [FINDINGS.md](FINDINGS.md).

Code changes:

- `GET /version` and the API manifest report the `@parmana/api` package version (4.1.1), not a hand-typed `0.4.0`.
- Unknown routes return a JSON `404` with `code: ROUTE_NOT_FOUND`, not an HTML page.
- The installed `parmana-ops` command runs when started through its bin name. The fix is in the repository; a release containing it is needed.
- Hybrid signing is refused at start-up unless `SECONDARY_SIGNATURE_PROVIDER` is set and differs from the primary.
- Production refuses memory storage at start-up (the default when `PARMANA_STORAGE` is unset). This reverses an earlier test's expectation; the owner should confirm it ([FINDINGS F0](FINDINGS.md#f0-production-with-memory-storage-is-now-refused-a-reversal-to-confirm)).
- `scripts/generate-approver-key.ts` creates its output folder.
- The retired `PARMANA_ALLOW_UNGOVERNED_POLICY` flag is removed from the examples runner, the load test and tutorial 81.
- The TypeScript workspace test script runs with the root configuration, and the six empty test files are removed. `npm test --workspace=typescript` passes with no extra environment.
- Corrected comments: the schema 3 gate in `Config.ts`, and the `PARMANA_KEY_DIR` requirement in `.env.example`.
- Tutorials 60, 103 and 120 state the environment they need.
- The existing quickstart page is corrected: the policy and key directories, and a warning about the approval step.

Portal changes: every statement that described a fixed defect was updated, and the generated error reference and `llms-full.txt` were regenerated.

Open, and not changed (see [FINDINGS.md](FINDINGS.md)): the schema 2 default (F1), the SDK's legacy-record result (F2), the dev setup (F3), Python `version` versus TypeScript `version()` (F4), two `0.1.0` packages (F5), the Policy v2 contract (F6), approval automation (F7), the Docker, database and load checks (F8, F9), the Python and Node verifier test-count difference (F10), third-party reading of schema 3 (F11), the declared-transaction approval rule (F12), and unknown routes without a key (F13).

## 2026-11-20: first version of the developer portal

Added the developer portal in `docs/developer-portal/`, written from the repository's source and checked against it:

- **Portal structure:** overview, getting started, architecture, SDKs, REST API, tutorials, policy management, deployment, security, troubleshooting, reference, FAQ, glossary, examples, and this changelog.
- **SDK references:** `@parmana/sdk` (58 methods) and `parmana` (50 methods), each with a generated method index that gives every signature and the HTTP request each method sends. Also the offline verifier (`@parmana/verifier`, `parmana-verifier`), the operator CLI (`@parmana/cli`), and the connector SDK's contract.
- **REST API:** authentication, headers, errors, status codes, and the core endpoints with `curl`, JavaScript and sample responses. A generated index lists all 66 OpenAPI operations.
- **Tutorials:** Node.js, Python, fintech, refund authorization, maker-checker, transaction limits, AI agents, and evidence verification.
- **Security:** what is signed, canonical JSON and hashing, trust roots, schema versions and their coverage, tamper results, fail-closed behaviour, key management, and a production checklist.
- **Runnable examples:** a governed quickstart kit (setup script, TypeScript and Python flows, approval and limit cases, a REST smoke test, and a standalone verification script). Each was run against a local server for this release.
- **Tools:** `tools/generate-indexes.mjs` regenerates the method, endpoint and error-code indexes from source. `tools/check-docs.mjs` checks links and anchors, reports public methods and operations not named in narrative pages, and flags removed claims.
- **Coverage report:** [COVERAGE.md](COVERAGE.md), with the verification log, sixteen known issues found during this review, and the remaining gaps.

Documented findings that need an owner decision (none were changed in the repository):

- The existing quickstart does not run as written.
- The server reports version `0.4.0` while the packages are `4.1.1`.
- The installed `parmana-ops` binary prints nothing.
- Schema version 2 records leave most fields outside the signature. Schema version 3 is opt-in.
- A stale comment in the configuration describes schema version 3 as unreadable by the SDKs. Those SDKs read it correctly.
- The TypeScript workspace's `npm test` fails: six test files are empty.

Not changed: the server, the packages, the existing documentation site (`docs/site/`), the existing guides, the tests and the examples. The portal is not published, and the proposed navigation for the documentation site is not applied.

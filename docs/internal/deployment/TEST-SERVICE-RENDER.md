# Test deployment of the Parmana API on Render

Purpose: a test service the inbound refund pilot calls (RFC-0025). It uses Test Mode keys and holds
no real partner key. It is not approved for production. Each step below was run on 2026-11-02.

## What is deployed

- Repository: `pavancharak/parmana-core`, branch `claude/outcome-endpoint`.
- Render web service, Docker build (`Dockerfile`, root). The build copies the packages and runs the
  API with `docker/entrypoint.sh`. Render's Node build command in the earlier plan is not used.
- URL: `https://parmana-core.onrender.com`.
- Health: `GET /health` returns 200. `POST /v1/inbound/decisions` without a key returns 401.

## Database

- The sandbox Supabase project (`parmana-connectors and sandbox`). It is labelled PRODUCTION in
  Supabase, and it is shared with the sandbox. Test rows from this service live there.
- All migrations were applied with `scripts/apply-all-migrations.sql` (the bundle is regenerated by
  `npm run generate:migration-bundle`). The bundle is safe to re-run: every create is guarded.
- The rate limiter needs `rate_limit_counters`. Without the migrations the service logged
  `relation "rate_limit_counters" does not exist` on every request.
- Check the tables: `select tablename from pg_tables where schemaname = 'public' order by tablename;`

## Environment variables

| Name                        | Value                                                                                          | Note                                                                |
| --------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| `NODE_ENV`                  | `production`                                                                                   | Turns off test-mode bypasses.                                       |
| `HOST`                      | `0.0.0.0`                                                                                      | Set by the container.                                               |
| `PARMANA_STORAGE`           | `postgres`                                                                                     | Without it, grant changes live in memory and are lost on restart.   |
| `DATABASE_URL`              | the Supabase connection string                                                                 | Secret. Copy from the project's Connect panel.                      |
| `PARMANA_POLICY_DIR`        | `./policies`                                                                                   | Committed.                                                          |
| `PARMANA_KEY_MATERIAL_JSON` | JSON with `default` and `gateway` entries, each with `privateKeyPem` and `publicKeyPem`        | Secret. Startup fails without a `default` key.                      |
| `PARMANA_GATEWAY_KEY_ID`    | `gateway`                                                                                      | Startup fails without it when `INBOUND_AUDIENCE` is set.            |
| `PARMANA_API_KEYS`          | JSON array of `{callerId, keyHash}` plus optional `credentialHolderType` and `stepUpPublicKey` | Secret. Replace the whole value on every change.                    |
| `INBOUND_AUDIENCE`          | `billing.example`                                                                              | Mounts the inbound routes. Without it, `/v1/inbound/*` returns 404. |

Every variable above is needed. Other settings in `.env.example` keep their defaults. Do not set
connector values on this service.

## Keys

- Generate caller entries with `npx tsx scripts/generate-api-key.ts -- --caller-id <id>`. Add
  `--credential-holder-type USER` for a person. Add `--generate-step-up-key` for a checker, which
  also needs the USER flag.
- The script prints the raw key and any step-up private key once. Nothing stores them. Store the raw
  key with its owner and the step-up private key with the checker.
- `PARMANA_KEY_MATERIAL_JSON` is generated locally with an Ed25519 pair for `default` and one for
  `gateway`. Store the value only in Render.
- The published public keys are at `https://parmana-core.onrender.com/.well-known/jwks.json`. The
  pilot pins the `gateway` public key from there.

## Problems met on the first deploy, and their fixes

1. **Build fails with `npm ci`** when no lockfile is committed. Commit the lockfile.
2. **`PARMANA_API_KEYS must be a JSON array`**. The value was a single object, not a list, or was
   pasted into the middle of another value. Replace the whole value with one array.
3. **`Signing key material for keyId "default" is missing`**. The key material must hold a `default`
   entry as well as `gateway`.
4. **`INBOUND_AUDIENCE is set, but PARMANA_KEY_MATERIAL_JSON does not hold a private key for PARMANA_GATEWAY_KEY_ID`**.
   Set `PARMANA_GATEWAY_KEY_ID=gateway`.
5. **`relation "rate_limit_counters" does not exist`** and a 500 on every request. Apply the
   migrations to the database the service uses.
6. **`/authority-grants` returns 404 under `/v1`**. The grant routes are mounted at
   `/authority-grants`, without `/v1`.
7. **A pending grant change disappeared after a redeploy.** The store was in memory. Set
   `PARMANA_STORAGE=postgres`.

## Verify

1. `GET /health` returns 200.
2. `POST /v1/inbound/decisions` with no key returns 401.
3. A decision request with a valid partner key returns 201 with a signed decision. Verify the
   signature with the pinned gateway public key.
4. Run the pilot's end-to-end test (see `for-pilots/docs/OPERATIONS.md`).

## Operating notes

- The free plan spins the service down when idle. The first request can take about 50 seconds.
- A redeploy restarts the service. Do not approve a grant change while a deploy is running.
- Rotate keys after any chat, email or screenshot that showed them.

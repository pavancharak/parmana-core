# Ed25519 (local key file)

**Production ready: yes.** This is the signer the production deployment uses today. Claim 3.13 says Ed25519 alone is what runs "everywhere this codebase runs today, including the production deployment".

## What it is

Ed25519 signatures over canonical records, made with a key pair in `PARMANA_KEY_DIR` (key ID `default`). Implemented by `Ed25519SignatureProvider` and loaded by `FileKeyProvider`. Verification is offline, with `verifyExecutionTrustRecordOffline` in the crypto package, the Python and TypeScript SDKs, and the separate verifier.

## Status

- **Built:** yes.
- **Tested:** yes. The Ed25519 and offline-verifier unit tests pass in the local sandbox, including tamper detection, wrong-key rejection, and fail-closed handling of unknown algorithms.
- **In production:** yes, Ed25519 alone (claim 3.13).

## How it is used

- Set `KEY_PROVIDER=local` (the default) and point `PARMANA_KEY_DIR` at the key files.
- Keys are loaded at startup from a secret manager, not from an environment variable (claim 2.58).

## Why it is ready

- It is the only signer that has run in production.
- Every record it signs can be checked offline, with no network and no database.

## Limits to know about

- **Not post-quantum.** Ed25519 is not secure against a future quantum computer. That is the reason for ML-DSA-65 and the hybrid signer, which are not yet deployed.
- **Key custody is a file.** The key lives on the server's disk. Use AWS KMS (see [aws-kms.md](aws-kms.md)) to remove the key from the server; the production key provider is not confirmed in the repo.

## When it changes

Nothing needs to change for Ed25519 to stay in production. The open items are key custody (KMS) and post-quantum migration, both covered in the other files.

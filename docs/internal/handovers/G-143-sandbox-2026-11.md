## 2. What the code does (G-143)

- An approved inbound decision that used a verified human approval records four fields: `approved_by`, `approved_at`, `approval_id`, `approved_key_id`. They are set only on an approved decision, and only from the verified approval, never from the partner's request.
- Each approval is single-use. It is consumed in the same database transaction as the decision record. If the record can't be written, the approval is not consumed.
- A second use of an approval is refused with `approval_already_used`, and no decision is recorded for that second request.
- Expired consumed-approval nonces can be pruned with `scripts/prune-approval-nonces.ts` (PR #525, merged). `--dry-run` only counts rows. Whether to schedule it is an owner decision (retention).

Main files: `packages/approval/src/ApprovalSignalVerifier.ts`, `packages/runtime/src/RuntimeEngine.ts`, `packages/api/src/routes/inbound-checks.ts`, `packages/storage/src/supabase/SupabaseInboundCheckRepository.ts`, `packages/storage/src/memory/MemoryInboundCheckRepository.ts`.

## 4. Sandbox test setup (PR #526)

The consumption suite (`packages/storage/tests/integration/supabase-inbound-check-consumption.integration.test.ts`) now picks its database like this:

1. `TEST_DATABASE_URL`, if set. It refuses to run if it equals `DATABASE_URL`.
2. Otherwise `DATABASE_URL`, but only with `ALLOW_LIVE_SUPABASE=1`. That is the same opt-in the other live suites require.
3. Otherwise it skips.

Local `.env.test` (gitignored, on each developer's machine). `vitest.setup.ts` loads it before `.env`, so its values win over production values in `.env`:

```
DATABASE_URL=<sandbox connection string>
ALLOW_LIVE_SUPABASE=1
PARMANA_DATABASE_CA_FILE=
TEST_DATABASE_URL=
```

Problems met while setting this up, and their fixes:

- `.env` contained a `TEST_DATABASE_URL` line, which made the refusal guard fire. Fix: set `TEST_DATABASE_URL=` (empty) in `.env.test`.
- `.env.test` was a copy of the template, so it held the local Docker `DATABASE_URL` first (dotenv uses the first occurrence) and had `ALLOW_LIVE_SUPABASE` commented out. The tests skipped silently. Fix: replace the whole file with the four lines above.
- The branch checkout on Windows was blocked by local edits to `package.json`, `package-lock.json` and `.gitignore`. Those edits were stashed as "local changes before PR 526" on `feat/razorpay-payment-signal`. Nothing was discarded.
- The branch for PR #526 was force-updated after its merge, to put the handover commit on top of `main`. The force-push was blocked once by the permission system; it was then run by hand with `--force-with-lease`, which only replaces the expected commit.

The runbook section for this is `docs/internal/runbooks/INTEGRATION-TESTS.md`, section 3a.

## What the sandbox is

The sandbox at `https://parmana-sandbox.vercel.app` runs the same server code as production, with
`PARMANA_SANDBOX=true`, its own database, its own signing keys and its own approver. It has one capability,
`sandbox:receipt`, released to an endpoint that acts on nothing and answers with a receipt. The server refuses to start
in sandbox mode if any connector to a real system is configured.

In the sandbox anyone can get a signed approval, from `POST /sandbox/approvals`. That shows how an approval is used,
not who may give one. In production only registered approvers sign.

## What the live check showed

The check uses only the demo key, which may ask for `sandbox:receipt` alone. On 2026-10-23:

1. The key's scope is `sandbox:receipt` only.
2. Policy `sandbox-receipt` 1.0.0 is in effect, approved through maker checker.
3. A request with no approval is refused with the policy's reason.
4. A demo approval is issued (`201`).
5. With it, the request is approved and released to the receipt endpoint, and the signed record verifies offline. It
   took 14.1 seconds.
6. The same approval used again is refused.
7. A note over 200 characters is refused by the policy.
8. A demo approval for another capability is refused (`400 INVALID_SANDBOX_APPROVAL_REQUEST`).
9. A browser request is allowed from the docs site and refused from any other site.

## Limits

- **Records are not deleted yet.** Deleting sandbox records older than 7 days, daily, is planned but not running. Do
  not send anything to the sandbox you would not want kept.
- **The sandbox maker and checker keys are held by one person.** They are distinct credentials, not proven distinct
  people.
- **An approved request is slow**, about 14 seconds.

The claim and its evidence are in `docs/CLAIMS.md`, section 2.51.

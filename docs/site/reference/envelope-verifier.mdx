  dependencies, only `@parmana/shared` and `@parmana/crypto`.
</Info>

## Purpose

Lets a receiving system verify a [signed execution authorization](/concepts/execution-authorization)
without trusting Parmana's runtime process or database, only Parmana's public key and the
envelope itself. This is what [The gateway](/concepts/the-gateway) composes and adds exactly
one more check to (`businessTransactionHash`).

## Install

Not published to npm. This is an internal package of this repository, used from a clone of it: `npm ci` at the repository root links every workspace package. The packages published to npm are [`@parmana/sdk`](/sdks/typescript), [`@parmana/connector-sdk`](/reference/connector-sdk).

## Key exports

| Export                                  | Stability                                                                                                                                                                                                                                                                                              |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `EnvelopeVerifier`                      | [AVAILABLE]. `new EnvelopeVerifier({ publicKey, nonceStore })`, `.verify(authorization): Promise<VerificationResult>`. Checks version, signature, expiry, TTL policy, and nonce, in that order, side-effect-free checks first. Does **not** check `businessTransactionHash`, that's the gateway's job. |
| `NonceStore` (interface)                | [AVAILABLE]. `{ hasSeen(nonce), markSeen(nonce) }`.                                                                                                                                                                                                                                                    |
| `MemoryNonceStore`                      | [AVAILABLE]. The only implementation shipped. Scoped to one process, loses state on restart, multiple independent instances each accept the same nonce once.                                                                                                                                           |
| `requireParmanaAuthorization(verifier)` | [AVAILABLE]. Express middleware, `@parmana/envelope-verifier/express` entry point (kept separate so consumers who don't use Express never pull in Express types). Reads `req.body.authorization`, verifies it, calls `next()` or responds 401/403.                                                     |

## `VerificationResult` shape

```typescript
interface VerificationResult {
  readonly valid: boolean;
  readonly checks: {
    readonly versionSupported: boolean;
    readonly signatureVerified: boolean;
    readonly notExpired: boolean;
    readonly ttlWithinPolicy: boolean;
    readonly nonceUnseen: boolean;
  };
}
```

Each check is reported independently, a caller can distinguish "forged" from "expired"
rather than getting one opaque `false`, verified live in [Detect tampering](/guides/detect-tampering).

## What each time check enforces

| Check             | Passes when                                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------------------------ |
| `notExpired`      | The verifier's clock (`now`, default the current time) is before `expiresAt`.                                |
| `ttlWithinPolicy` | All three conditions below hold. The name is kept for compatibility, and the check covers more than the TTL. |

`ttlWithinPolicy` requires all of the following:

1. **A positive lifetime.** `expiresAt` is after `authorizedAt`. An envelope whose expiry precedes its issue time is refused, even when its signature verifies.
2. **A lifetime within the policy maximum.** `expiresAt - authorizedAt` is at most `maxTtlSeconds`. The constructor option defaults to 300 seconds, so a compromised signer cannot mint long-lived envelopes.
3. **No future-dated issue time.** `authorizedAt` is no more than 60 seconds after the verifier's clock. The 60-second allowance is fixed and is the same as the policy-change step-up verifier's. An envelope issued by a signer whose clock runs further ahead is refused until the clocks agree.

`maxTtlSeconds` is the only time setting you can change. The 60-second skew is a constant in the package. If your signer and verifier clocks drift by more than 60 seconds, correct the clocks rather than the verifier.

Refused envelopes return `valid: false`. The check that failed is reported in `checks`: `notExpired` for an expired envelope, `ttlWithinPolicy` for any of the three conditions above.

```typescript
const verifier = new EnvelopeVerifier({
  publicKey,
  nonceStore: new MemoryNonceStore(),
  maxTtlSeconds: 120, // refuse envelopes valid for more than two minutes
});
```

## Minimal example

```typescript
import { EnvelopeVerifier, MemoryNonceStore } from "@parmana/envelope-verifier";

const verifier = new EnvelopeVerifier({
  publicKey,
  nonceStore: new MemoryNonceStore(),
});
const result = await verifier.verify(authorization);
// result.checks.signatureVerified === false if forged, distinct from result.checks.notExpired
```

<Info>
  **[AVAILABLE]**. The offline verifier is a separate, public repository:
  [`pavancharak/parmana-verifier`](https://github.com/pavancharak/parmana-verifier),
  Apache License 2.0. The Node version requires Node.js 24 or later and has no
  dependencies. It is published on npm as
  [`@parmana/verifier`](https://www.npmjs.com/package/@parmana/verifier). A
  Python version, for Python 3.11 or later, is published on PyPI as
  [`parmana-verifier`](https://pypi.org/project/parmana-verifier/).
</Info>

It recomputes an Execution Trust Record's hash and checks its signatures against the keys you
pin in a trust file. It makes no network calls, so a result does not depend on Parmana's servers
or database.

## Run it

Install it, or run it without installing:

```sh
npm install -g @parmana/verifier
parmana-verify <proof.json> <trust.json>
parmana-verify key-fingerprint <public-key.pem>
```

```sh
npx @parmana/verifier <proof.json> <trust.json>
```

From a clone of `parmana-verifier`, use `node bin/parmana-verify.mjs` in place of `parmana-verify`.

### Python

The Python version has the same checks, output and exit codes. It needs the `cryptography`
package. Install it from PyPI:

```sh
pip install parmana-verifier
parmana-verify <proof.json> <trust.json>
```

Or install from a clone of the repository:

```sh
git clone https://github.com/pavancharak/parmana-verifier
cd parmana-verifier/python
pip install -e .
```

It does not check ML-DSA-65 (hybrid) signatures, because `cryptography` does not provide them.
A hybrid record is reported as invalid. Use the Node version to check those records.

- `proof.json` is the Execution Trust Record.
- `trust.json` lists each key you accept:

```json
{
  "keys": [
    {
      "keyId": "default",
      "algorithm": "ed25519",
      "publicKeyPem": "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----\n",
      "fingerprint": "sha256:<64 hex digits>",
      "validFrom": "2026-01-01T00:00:00.000Z",
      "validUntil": null,
      "compromised": false
    }
  ]
}
```

The command prints one line of JSON and exits with `0` when the record is valid, `1` when it is
invalid (with the reasons), and `2` for a usage error, a missing file or invalid JSON.

## Pin a key

1. Get the operator's public key and the `sha256:` fingerprint they published. Get the fingerprint
   from a source other than the one that gave you the key, such as a signed message.
2. Run `parmana-verify key-fingerprint public-key.pem` on the PEM you received.
3. Compare the two fingerprints character by character. If they differ, do not use the key.
4. Only then add the key to your trust file with that fingerprint.

## Trust rules

A key is used only when all of these hold:

- its PEM hashes to the pinned fingerprint (SHA-256 of the SPKI DER encoding);
- the algorithm named by the signature matches the algorithm in the trust file;
- it is not marked `compromised`;
- the record's `createdAt` is at or after `validFrom` and before `validUntil`, if set.

A compromised key is rejected whatever the timestamp, so signatures it made stay void.

## What it does not show

- It shows that a record was signed by the key you pinned. It cannot show that the key belongs to
  Parmana; that depends on how you obtained and compared the fingerprint.
- For schema version 2 records, only the fields listed in the repository's format document are
  protected. For schema version 3, every field except the signature envelope, `verifications` and
  `receipts` is protected. Check that `coverage` is `full` when that matters.
- It does not check the policy a record cites, the decision logic, or whether the action reached
  the external system.

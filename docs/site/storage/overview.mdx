## Providers, precisely

```typescript
// packages/storage/src/StorageFactory.ts (abridged)
switch (configuration.provider) {
  case "memory":
    return new MemoryStorageProvider();
  case "supabase":
  case "postgres":
    // refuses with a named error when DATABASE_URL is not set
    return new PostgresStorageProvider();
  case "sqlite":
    throw new Error("SQLite storage provider not implemented.");
}
```

`postgres` is the name to use. `supabase` is accepted as an alias for the same implementation, so existing configurations keep working. The implementation is `PostgresStorageProvider` for historical reasons: it writes through a direct PostgreSQL connection (`DATABASE_URL`) with the `pg` driver, not through a Supabase client. A self-hosted PostgreSQL works the same way, and so does a Supabase-hosted database. Both refuse to start without `DATABASE_URL`. `sqlite` throws at startup, by design (fails closed rather than silently falling back).

| Provider   | Status                    | Notes                                                                                                                                 |
| ---------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `memory`   | [AVAILABLE]               | In-process, non-persistent. Used throughout this site's live examples (`PARMANA_STORAGE=memory`) so they have no external dependency. |
| `postgres` | [AVAILABLE]               | `PostgresStorageProvider` over `DATABASE_URL`, using `pg`. Works with any PostgreSQL 16 database built from `supabase/migrations/`.   |
| `supabase` | [AVAILABLE]               | Alias for `postgres`. Kept for existing configurations.                                                                               |
| `sqlite`   | Declared, not implemented | Throws at startup.                                                                                                                    |

## What's stored

Business Transactions and Execution Trust Records (the append-only ledger behind every
[Execution Trust Record](/concepts/execution-trust-records)), Execution Intents, Refusal
Records, pending policy changes and their signed approval records, approval issuers,
external connectors, the execution and caller audit events, and the single-use nonces for
authorizations, approvals and step up envelopes. Each has a `Memory*` implementation for
tests and a PostgreSQL implementation; see `packages/storage/src/index.ts`.

The evidence tables are append-only at the database level: the caller audit, execution
audit, policy change approval and refusal record tables reject `UPDATE`, `DELETE` and
`TRUNCATE` through triggers (migration `20261110120000_enforce_append_only_evidence.sql`).
See [Storage schema](/storage/schema-reference) for the full list.

## Configuration

```bash
PARMANA_STORAGE=memory     # or postgres (needs DATABASE_URL)
```

`PARMANA_STORAGE` is the only variable read. An older `DATABASE_PROVIDER` variable existed
briefly as a second, disconnected path to the same setting and is now retired: if it's
present in the environment, config loading fails at startup naming `PARMANA_STORAGE` as the
replacement, rather than silently ignoring it. Tests: `packages/storage/tests/`.

See [@parmana/storage](/reference/storage) for the package's full export list if you're
consuming it directly rather than through the default server.

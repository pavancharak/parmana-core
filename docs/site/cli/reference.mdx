## Global options

These work with every command.

| Option                | Meaning                                                   |
| --------------------- | --------------------------------------------------------- |
| `--output` `<value>`  | Output format: text (default) or json.                    |
| `--profile` `<value>` | Named API address from the config file.                   |
| `--api-url` `<value>` | API address; overrides PARMANA_API_URL and the profile.   |
| `--dry-run`           | Print the request without sending it.                     |
| `--verbose`           | Log each request and response code, with secrets removed. |
| `--timeout` `<value>` | Seconds to wait for each request (default 30).            |
| `--help`              | Show help for this command.                               |

## `policy status`

List pending policy changes for one policy version.

```bash
parmana policy status <name> <version>
```

### Options

This command takes no options of its own.

### Environment

- `PARMANA_TOKEN`
- `PARMANA_API_URL`
- `PARMANA_PROFILE`
- `PARMANA_CONFIG`

### Example

```bash
parmana policy status customer-refund 1.3.0
```

## `policy propose`

Propose a policy change. The file must match the name and version.

```bash
parmana policy propose <policy.json> --name <name> --version <version> --reason "<why>"
```

### Options

| Option                | Meaning                                              |
| --------------------- | ---------------------------------------------------- |
| `--name` `<value>`    | Policy name; must equal the file's policyId.         |
| `--version` `<value>` | Policy version; must equal the file's policyVersion. |
| `--reason` `<value>`  | Why the change is needed. Required.                  |

### Environment

- `PARMANA_TOKEN`
- `PARMANA_API_URL`
- `PARMANA_PROFILE`
- `PARMANA_CONFIG`

### Example

```bash
parmana policy propose policy.json --name customer-refund --version 1.3.0 --reason "Refuse all refunds" --dry-run
```

## `approval sign`

Sign a step-up envelope on the checker's own machine. Nothing is sent.

```bash
parmana approval sign --key-file <private.pem> --key-id <id> --pending <id> --action <approve|reject> [--out <file>]
```

### Options

| Option                 | Meaning                                                             |
| ---------------------- | ------------------------------------------------------------------- |
| `--key-file` `<value>` | The checker's step-up private key (PEM). Never leaves this machine. |
| `--key-id` `<value>`   | The key label the operator registered for the checker.              |
| `--pending` `<value>`  | The pending change ID.                                              |
| `--action` `<value>`   | approve or reject.                                                  |
| `--out` `<value>`      | Write the envelope to this file instead of stdout.                  |

### Environment

This command reads no environment variables.

### Example

```bash
parmana approval sign --key-file .\checker.step-up.private.pem --key-id mamta-checker --pending <id> --action approve --out envelope.json
```

## `approver propose-add`

Propose adding an approver key, granted the listed capabilities.

```bash
parmana approver propose-add --approver <id> --key <id> --public-key-file <pem> --capabilities <a,b> --reason <why>
```

### Options

| Option                        | Meaning                           |
| ----------------------------- | --------------------------------- |
| `--approver` `<value>`        | The approver ID.                  |
| `--key` `<value>`             | The key ID.                       |
| `--public-key-file` `<value>` | The Ed25519 public key, PEM.      |
| `--capabilities` `<value>`    | Comma-separated capability names. |
| `--reason` `<value>`          | Why the key is being added.       |

### Environment

- `PARMANA_TOKEN`
- `PARMANA_API_URL`
- `PARMANA_PROFILE`
- `PARMANA_CONFIG`

### Example

```bash
parmana approver propose-add --approver pavan --key pavan-key-1 --public-key-file pavan.public.pem --capabilities razorpay:refund --reason rotation --dry-run
```

## `log verify`

Check the approval log's chain, signatures and policy coverage. Offline.

```bash
parmana log verify [--policy <name>] [--base <ref>] [--require-coverage]
```

### Options

| Option               | Meaning                                         |
| -------------------- | ----------------------------------------------- |
| `--policy` `<value>` | Check only this policy.                         |
| `--base` `<value>`   | Git ref; check that the log only grew since it. |
| `--require-coverage` | Fail if a policy file has no logged approval.   |

### Environment

This command reads no environment variables.

### Example

```bash
parmana log verify --require-coverage
```

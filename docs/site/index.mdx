**The Business Authority Layer for Autonomous Systems.**

AI agents can propose and start actions. Institutions decide what authority to delegate. Parmana checks each action against that authority before it runs, and keeps signed evidence that anyone can verify.

## Access is not authority

Access controls answer one question: can this agent reach this system? That matters, but it is not the question that matters when an agent is about to issue a refund or change a record. The question is whether this specific action, for this amount and in these circumstances, is within what your institution actually delegated.

Parmana answers that question before the action runs, using rules your institution writes and a person's signature where the rules require one.

## What Parmana controls

1. **Declared.** Your institution writes its authority as explicit, versioned rules: what each action may do, up to what amount, and when a person must approve it.
2. **Authorized.** Each proposed action is checked against those rules. If no rule matches, the action is refused. A rule that needs a person waits for a signed approval for that exact action.
3. **Executed.** Only permitted actions pass the enforcement boundary. On supported paths, the gateway holds the connector credentials, so the agent never does, and it releases each approved action once.
4. **Proven.** A signed record of the decision and the release, which anyone can verify offline with the public key they choose to trust.

Each stage is built and tested. [How Parmana thinks](/how-parmana-thinks) sets out what each stage guarantees, and where it stops.

## An example

A support agent asks to refund 4,000 to a customer. Your policy lets the agent refund up to 500 on its own. Above 500, it needs a signed approval from a named manager for that order and that amount.

Parmana refuses the request, so nothing is refunded. The manager reviews it and signs an approval for that order and amount, valid for 15 minutes and usable once. The agent sends the request again. Parmana releases the refund through your refund system, and the record shows the decision, the approval and the release.

## What the institution receives

- **Control.** Rules you can read, change only through a second approver, and enforce whether the caller is a person or an agent.
- **Accountability.** A signed record of each decision, approval and release, tied to the action it covers.
- **Independent evidence.** Records that an auditor or regulator can verify without access to your systems or to Parmana.

## What Parmana is not

Parmana does not replace identity and access management, AI security tools or AI governance. Each answers a different question, and Parmana sits after them, in front of the actions an agent takes. [How Parmana compares](/how-parmana-compares) sets out the difference.

## Where Parmana stands

Parmana is a prototype. It checks only actions that go through its gateway, and it does not read the text a model produces. Every claim, with its evidence and its limits, is recorded in the repository.

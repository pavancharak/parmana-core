Status

Parmana is a prototype.

We would rather you know the limits now than find them in production. This page lists what works, what does not, and what is not yet built.

Available today

  • Declared, versioned authority rules, checked per action with its exact parameters. No matching rule means refusal.
  • Signed human approval bound to one action, resource and amount, single use and expiring.
  • Credential isolation on supported paths: the gateway holds connector credentials.
  • Signed execution and refusal records, with four verification checks run on each verification.
  • Maker checker for policy, approver and connector changes.
  • Open source under the Apache License 2.0, including the server and the client and connector SDKs.

Known limitations

  • No text inspection. Parmana does not detect prompt injection, toxic output or data leakage in model text.
  • Covers only routed actions. There is no network-level enforcement.
  • Human approval on every action that needs it. Latency is by design.
  • Declared facts are not checked against your systems unless a policy names a business signal source. No shipped policy does yet.
  • Approvers are not yet scoped to particular actions or policies.
  • No ready-made connectors. Use a registered external endpoint or write a connector.
  • No metrics, tracing or dashboards yet. Key custody is local files or AWS KMS only.

Not yet built

The roadmap in the documentation lists planned work. Anything not in this list is not available, whatever a slide or a conversation suggests.
